# Web Guests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Someone opens a link in a browser, types a name, and is in the live layup — seeing the shared screen, heard and hearing, with a cursor the others can watch. No install, no account, no org membership.

**Architecture:** A guest is a `domain.UserID` with a `usr_g` prefix that the directory never lists, so presence and the People grid exclude them for free while every layup, membership and signalling path works unchanged. A guest session token is authorised by an **allow-list** of endpoints scoped to one layup. The web client is a new Vite workspace reusing `apps/desktop/src/core` — which imports nothing from Node or Electron — through a path alias.

**Tech Stack:** Go 1.26.4 (stdlib only), Vite 7, React 19, TypeScript 5.9, Caddy.

**Spec:** `docs/superpowers/specs/2026-08-17-web-guests-design.md`

## Global Constraints

- **No new Go dependencies.** `crypto/rand`, `crypto/subtle`, `sync`, `encoding/json` cover it.
- **A browser is a hostile client.** Every guest limit is enforced server-side. Client-side checks make the UI honest, never safe.
- **Authorisation is an allow-list, not a deny-list.** A new endpoint must be closed to guests by default.
- Guest tokens are 32 bytes from `crypto/rand`, base64url, unpadded, and **never appear in a URL path, a query string, a log line, or browser history**.
- Guests are **never** returned by `directory.Users()`. That single exclusion keeps them out of presence (`presencefeed/feed.go:119`) and the People grid.
- Nothing about a guest is persisted. Not in `identities.json`; a restart does not resurrect them.
- **Naming trap:** `domain.CreateLayupWithGuests(ctx, in, guests ...UserID)` already exists and its "guests" means *the other invited user* — nothing to do with web guests. Do not conflate them. New code uses `GuestSession` / `guestStore` and never changes that function's meaning.
- All existing tests pass — currently 570 desktop, 33 protocol, all Go. `make check` green, `make test-boundary` → `BOUNDARY OK`.
- **Do NOT run `npm run test:smoke`** — 5 pre-existing failures, bisected to before this branch.

### Task 1: Close the token-in-path leak

`POST /api/links/{token}/join` (`httpapi/server.go:154`) puts a 128-bit token in the **URL path**. Caddy's log filter redacts query strings, not paths, so every guest token would land in `/var/log/caddy/layup.log` in cleartext. Deferred while the endpoint was unused; load-bearing now.

**Files:** Modify `services/control/internal/httpapi/links.go`, `server.go`, `links_test.go`.

**Interfaces:** Produces `POST /api/links/join` taking `{"token": "..."}` in the body. Consumed by Task 5.

- [ ] **Step 1: Write the failing test.** `POST /api/links/join` with the token in the JSON body joins the layup; the old path-based route no longer exists (404).
- [ ] **Step 2: Run it, watch it fail.** `cd services/control && go test ./internal/httpapi/ -run Link -v`
- [ ] **Step 3: Implement.** Add the body-based route, remove the path-based one, keep the constant-time `resolve`. Update `links_test.go` — it is the only caller.
- [ ] **Step 4: Prove the token cannot be logged.** Assert the token appears in no log line for a successful and a failed redemption, matching the existing redaction discipline.
- [ ] **Step 5: Verify.** `go test ./... && go vet ./...`, `gofmt -l .` clean.
- [ ] **Step 6: Commit.** `git commit -m "control: redeem a link from the body, where a log cannot see it"`

## Done when

- A link opened in a browser puts a named guest in the live layup, seeing the screen, heard, and pointing.
- A guest token is refused on every endpoint outside its allow-list, including one nobody remembered to list.
- A guest appears in the layup's participants and in nobody's People grid.
- A guest cannot be granted remote control, refused independently by the server and by `input-guard.ts`.
- No guest token appears in any log line or URL path.
- `make check` and `make test-boundary` green; 0.3.0 auto-updates from 0.2.1.
